PR-9 排班闭环：停诊申请 + 跨科室改约 + 站内信
时间：2026-11-05 22:55—23:25
目标：把"医生想停诊 → 管理员处理 → 患者知情"整条链闭合

一、闭环链路
医生排班页「申请停诊」（含已约时段）
   → POST /doctors/me/suspend-requests
   → 管理端「停诊申请」角标 + 抽屉列表
   → 管理员审批：
        · 通过并退号 → changeStatusByAdmin(force=true) → 患者 CANCELLED(SUSPEND) + 站内信
        · 或到排班板用影响面 → 一键改约（可跨科室、可多时段）
   → 医生收到审批结果/停诊结果站内信
   → 患者收到「预约已取消」/「预约已改约」站内信，铃铛红点 + 消息详情

二、本次新增
1. 站内信（sm_notification）
   - 接口：GET /notifications、GET /notifications/unread-count、PUT /{id}/read、PUT /read-all
   - 事件：停诊退号、改约成功、停诊申请通过/驳回、号源被停诊（通知医生）
   - 前端：患者/医生布局右上角铃铛（未读角标、30s 轮询、全部已读）
2. 停诊申请（sm_suspend_request）
   - 医生：POST/GET /doctors/me/suspend-requests（校验归属、OPEN、未开始）
   - 管理：GET /admin/suspend-requests、GET /pending-count、PUT /{id}/review
   - 审批通过即执行退号停诊；若时段已被处理过则跳过执行，只记审批结果
3. 改约升级
   - 支持 toSlotIds 多目标：按余号顺序装人，容量不足整批回滚
   - 新增 GET /admin/schedules/alternatives：跨科室候选（含医生姓名）
   - 前端改约目标可多选、可按科室查找，实时显示"已选 X 个 / 可容纳 Y 人"

三、验证
1. mvn -o test：Tests run: 64, Failures: 0, Errors: 0 —— BUILD SUCCESS
   新增：跨时段拆分改约（余号 1 + 5 装 2 人，分别落到两个时段）。
2. HTTP 实测
   - 王医生（心内科）08:00 被患者预约 → 医生提交停诊申请 → 管理端 pending=1；
   - 审批通过 → 号源 SUSPENDED/booked=0；患者通知"预约已取消（医生停诊）"；
     医生通知"停诊申请已通过"+"您的号源被停诊"；
   - 多目标改约：1 位患者从 09:00 → [09:30, 10:00]，实际落到 09:30，返回 assignments；
     患者收到"预约已改约"（含新时段、新单号）；
   - 跨科室候选：department=心内科 返回王医生 08:30 余 5 / 09:30 余 4 / 10:00 余 5。
3. 浏览器实测（Edge headless）
   - 管理端抽屉展示王医生待审批申请（时段/原因/提交时间/驳回/通过并退号）；
   - 医生端 09:30 已约 1 人时按钮变为"申请停诊"，弹窗可填原因，下方展示我的申请状态；
   - 患者端铃铛显示 2 条未读，正文含新时段与新单号；
   - 三处 console 错误均为 0。

四、遗留
- 站内信仅站内可见，未接短信/公众号模板消息（接口已按事件类型设计，接通道即可）；
- 管理员新申请的实时推送未做（当前是进入页面拉角标）；
- 改约未保留"原单 → 新单"的显式链路字段（当前用 cancel_reason=RESCHEDULE + 通知正文表达）。
